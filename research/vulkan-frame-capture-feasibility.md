# Vulkan full-frame capture feasibility

Read-only assessment, 2026-11-13. **Investigate GFXReconstruct behind an imported-memory/address gate; RenderDoc is not a drop-in route for current Hookshot.** Neither tool is installed on PATH here. No capture, replay, device query, installation or implementation change was performed for this assessment. A valid trace could fix a submitted Vulkan workload for controlled comparisons, but does not establish historical CPU-input atomicity or native gameplay FPS.

## Documented support and actual blockers

| Area | Finding and scope |
|---|---|
| External guest memory | RenderDoc's release [extension matrix](https://github.com/baldurk/renderdoc/blob/b0e1370309f7d7bf986a73830446ca39d9b8c1fd/renderdoc/driver/vulkan/extension_support.md#unsupported) lists `VK_EXT_external_memory_host` and shader-module identifiers unsupported. Hookshot `memory_init` requires the host-memory extension, so extension filtering can stop initialization. GFXReconstruct [replay allocation code](https://github.com/LunarG/gfxreconstruct/blob/4401228c791b11fb7ea15b93795cbd1e938307c0/framework/decode/vulkan_replay_consumer_base.cpp#L6388) explicitly handles host imports. That alone does not prove capture of their bytes or aliases. |
| CPU writes during a frame | Hookshot imports an existing guest pointer and continues writing through it outside `vkMapMemory`. GFXReconstruct's [mapped-write capture path](https://github.com/LunarG/gfxreconstruct/blob/4401228c791b11fb7ea15b93795cbd1e938307c0/framework/encode/vulkan_capture_manager.cpp#L1354) tracks ordinary mapped memory; its allocation path does not visibly enroll the application's existing host-import pointer in that tracker. **Inference:** Linux page-guard/unassisted mode can miss subsequent original-pointer writes. Its documented external-page-guard option is Windows-only and injects tool-owned memory; it is not evidence that existing guest pointers are tracked. |
| Mesh/push descriptors/libraries | RenderDoc lists EXT mesh shaders, KHR push descriptors and graphics pipeline libraries as supported. GFXReconstruct's [generated replay](https://github.com/LunarG/gfxreconstruct/blob/4401228c791b11fb7ea15b93795cbd1e938307c0/framework/generated/generated_vulkan_replay_consumer.cpp#L11122) implements EXT direct/indirect/count mesh calls and push descriptors. These are API-support observations, not a successful Hookshot trace. Task payloads, image inputs and writable/atomic resources still need complete state. |
| Shader/pipeline identity | GFXReconstruct documents module replacement by captured handle; RenderDoc [builds task/mesh target shaders and rebuilds dependent pipelines](https://github.com/baldurk/renderdoc/blob/b0e1370309f7d7bf986a73830446ca39d9b8c1fd/renderdoc/driver/vulkan/vk_replay.cpp#L5265). Pin actual SPIR-V digests and every affected pipeline/library, rather than assuming one program hash equals one pipeline. Hookshot's optional identifier-only compute path can create a pipeline without submitting its code. `RX_VK_MODULE_IDS=0` is a diagnostic source-visible way to avoid that path; preserve work and verify resulting identities. No `VK_KHR_pipeline_binary` use was found in the examined Hookshot path; opaque pipeline-cache data is a separate concern. For substitution diagnostics, GFXReconstruct documents `--opcd` to omit opaque pipeline-cache data; require complete module code and rebuilt dependent libraries, then handle warm-cache performance separately. |
| Substitution policy | Replacing module bytes alone does not change required subgroup size, full-subgroup flags, specialization or layout. Original32 versus conditional8/16 needs a separately keyed pipeline-policy override and actual executable-width checks. GFXReconstruct's replacement path is explicitly a bytecode replacement, not that policy override. |
| Frame state and images | GFXReconstruct documents frame trimming with state/resource initialization, screenshots and resource dumps. Track from instance/device creation, then select a warm frame; attaching after objects and mappings already exist is not equivalent. Compare baseline against itself first, including storage/indirect outputs and images. Dumps, forced queue synchronization and capture instrumentation must be excluded from performance measurements. Trace timing is not native gameplay FPS. See the pinned [usage documentation](https://github.com/LunarG/gfxreconstruct/blob/4401228c791b11fb7ea15b93795cbd1e938307c0/USAGE_desktop_Vulkan.md). |

## BDA on the pinned E5/A770 stack

The receipt-matching E5 ANV source advertises `bufferDeviceAddressCaptureReplay=true`; this is a **source observation**, not a fresh device/capture test. Ordinary owned allocations can use the capture/replay mechanism, so arbitrary address-word patching should not be the default plan.

Host imports are the exception: Vulkan [VUID 03332](https://docs.vulkan.org/refpages/latest/refpages/source/VkMemoryAllocateInfo.html) requires their opaque memory capture address to be zero, and the pinned GFXReconstruct replay code explicitly does that. ANV's ordinary buffer address comes from its bound memory. Therefore the feature bit alone does **not** prove that imported pool addresses, the page-table root and every embedded page address will be reproduced. Require exact-address equality or complete semantic relocation. Scanning and replacing arbitrary 64-bit words is unsound.

`RX_VK_MIRROR=1` is insufficient: Hookshot still imports guest memory and performs upload/write-back transfers against it. A future copied-memory adapter would need to preserve all native features, dirty-write events, overlapping guest/backing aliases and ordering. No existing knob was established as a complete trace-safe copied mode.

## First gate before any game capture

First implement an independently authored **CPU source-unit check** for the pinned capture allocation/map/submit path: provide a host-import pointer, mutate it before and during trim boundaries without calling `vkMapMemory`, and require corresponding captured byte-update events. Check the original-pointer registration and alias interval identity, not merely serialization of `pHostPointer`. The current audited path appears to fail this requirement; that is a gate to investigate, not a claimed runtime failure.

Only after review, propose a small authored Vulkan fixture on the pinned stack: ordinary-allocation control, host-import writes before/during trimming, two overlapping buffer views, and a BDA root/page table feeding a checked output. Require repeated baseline output equality, exact GPU VAs or explicitly verified relocation, and alias-visible writes. Missing write events, changed table addresses without semantic relocation, lost aliases or unequal baseline replays reject the tool path before using game data. Add mesh/push-descriptor/library cases after the memory gate passes. **No GPU grant or execution is implied by this proposal.**

Even a passing fixture cannot recover passes the renderer omitted before capture, establish whole-game determinism, or replace the separate native-quality and historical-provenance gates. Captures and any extracted game shaders/assets must remain private; only sanitized metadata belongs in the public repository.
