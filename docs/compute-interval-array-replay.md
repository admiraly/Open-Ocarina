# Common23 owned array replay preparation

`tools/compute_interval_array_replay.py` prepares a new private runtime helper and three single-dispatch plans: original baseline once, original repeated and array once. **Preparation has made no Vulkan instance, device, pipeline or dispatch call. Each future case requires separate review and an exclusive GPU grant.** The Python command exposes preparation only. The earlier compile-only helper and all original `02` helpers, controls, source proofs and results remain unchanged.

This profile uses the same union layout as the [three-case compiler observation](compute-interval-array-compile-observation.md): original fourteen descriptors, the existing binding-12 record and eight binding-13 aliases. Both modules require nonuniform storage-buffer indexing, 23 push/resource slots, seventeen storage slots and the complete original feature/robustness profile. No variable-pointer feature is enabled. Both actual subgroup 32 and full subgroups are required. The recorded compiler policy is the E5 physical two-control policy with SHADOW and MAX absent.

The new helper is derived through counted edits from the hash-pinned `02` source `9b67fb…`. It applies the reviewed common23 descriptor/capability edits, then restores the byte-identical original resource helpers and dispatch tail. Its own ABI magic `OOARPL1` rejects old `02` and compile-only controls. Only the exact original `b9af52…` and array `7c6322…` modules are accepted; the static module is not admitted. The complete generated source diff and optimized helper hash are private preparation artifacts.

The original 59 allocation owners and the independent guarded record owner are unchanged. Array elements 0–4 alias bindings 2–6 element zero, and elements 5–7 alias binding 7 elements 0–2. CPU admission compares every owner, offset, range, null and auxiliary descriptor field with the original. After native descriptor construction, another check compares each pair's actual `VkBuffer`, offset and range, plus the `VkWriteDescriptorSet` target and pointer. The writable binding-6 alias is included. The two null pairs must use `VK_NULL_HANDLE`, offset zero and `VK_WHOLE_SIZE` on both sides. Equal copied bytes or a different buffer handle cannot satisfy this contract.

The future execution path retains exactly one dispatch of grid `[2,1,1]`, local `[64,1,1]`, original push bytes and page-table relocation logic. It retains the two-second fence bound and has no device/queue-idle failure wait. A future parent collector must bound the complete helper process to thirty seconds and combined pipes to 64 MiB, without child resource-limit overrides, and must claim each case once with an exact reviewed SHA. No runtime launcher or automatic retry/fallback is provided here.

All sixty complete buffers must be exported: 1,163,919,360 original bytes plus the 8,784-byte independently owned record and guards. Native comparison checks the guarded record against its unchanged initial file. Python comparison verifies every output file's exact size, rehashes every byte and checks receipt identities, actual width, alias counts, enabled features and all expected record bytes. Baseline and repeat must match all sixty buffers before the array case; array must match both baselines. A changed byte in an unwritten tail or record guard fails. This is a differential owned-input oracle, not an independently reconstructed game-output oracle or an as-submitted descriptor certificate.

CPU tests use independently authored framing data and a linker trap at `vkCreateInstance`. They reject wrong module/old ABI/grid, altered alias owner/range/null, missing record expectations and truncated descriptor lists. A pure-C synthetic handle harness rejects a different binding-6 alias buffer, changed offsets/ranges, wrong write targets and incorrect null construction. Thirteen capacity/feature mutations reject before any Vulkan call. Complete-readback tests mutate late bytes, truncate owners and alter record guards. The optimized helper's dynamic symbols retain the one dispatch/submit/fence path and exclude unbounded idle waits. A source comparison preserves original command recording through submission and original complete-output export semantics.

Preparation requires Python 3.11+, SPIRV-Tools, a C compiler, Vulkan development headers/loader/pkg-config and `nm`; reproducing the base source in synthetic tests additionally uses the documented `clang-format` version/settings. The [sanitized preparation](../research/compute-interval-array-replay-preparation.json) records final source, helper, diff, common-profile and all three plan hashes. No GPU capacities or runtime behavior were queried in this preparation. Native writer support, live descriptors, renderer integration, native-quality rendering and FPS remain unknown.
