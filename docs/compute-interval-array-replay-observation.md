Immediately before creating commands, native checks compare the actual constructed `VkBuffer`, offset and range of each original/alias pair, plus its descriptor-write target and info pointer. These checks passed in every case.

The E5 driver and physical two-control policy are unchanged: `HS_SPILL_BATCH=1`, `shader_spilling_rate=1`, SHADOW and MAX absent, and the other recorded controls absent. All runs use the same 23-element union, seventeen storage-buffer descriptors, two UBOs and four combined sampled-image/sampler descriptors. Original integer, BDA, robust-buffer, robustness2, null-descriptor, subgroup and other feature gates remain. The recorded thresholds passed before logical-device creation; exact maximum capacity values were not exported.

Every case had a fresh isolated empty writable cache, a distinct reviewed single-use claim, a thirty-second parent process bound, a two-second fence bound and combined stdout/stderr bounded to 64 MiB. No child resource limits were changed, no case retried, and no extra case ran. Read-only known game/helper scans passed before each launch, and the root agent granted an exclusive GPU lease. The scanner does not exhaustively exclude unknown or renamed GPU applications. The earlier static compile-only scan uncertainty remains recorded in its separate observation.

Compiler metadata stayed consistent with the earlier common23 compile-only results: original 144,485 instructions, 6,690 spills and 14,943 fills; array 89,834 instructions, 4,134 spills and 9,032 fills. Both require 32 KiB scratch. These are compiler statistics, not measured GPU costs. No shader timestamp query was issued. The process wall values in the JSON include compilation, uploads, submission, waiting and complete output export, so their ratio is not a shader speedup.

This covers one owned frozen diagnostic input graph, two original runs and one array run at subgroup 32. Original-buffer checks are differential against the repeated baseline, not an independently reconstructed CPU game-output oracle. The immutable record owner has its own independent byte expectation. Other input graphs, widths and drivers remain untested in this lane. The source selection proof describes the frozen input views; actual as-submitted descriptors and native candidate classification remain unestablished. The live renderer still lacks this new descriptor-array/record ABI. Image quality, native-feature parity, gameplay stability and FPS require separate integration and acceptance work.
